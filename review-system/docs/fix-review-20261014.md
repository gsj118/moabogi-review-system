## 환경·시험·회귀

- Windows의 기존 STS3/Spring5.3.39/JDK15/source·target1.8/Tomcat9/MySQL8.4/MyBatis 구성을 유지했다. Chrome에서 실제 JSP를 사용했다.
- 최종 Maven `BUILD SUCCESS`, 단위시험2·통합시험23, 실패0·오류0·skip0. 통합시험은 기존18개와 신규5개다. 최종 재실행 시간은 maven-results.json에 저장했다.
- 신규 통합시험: 실제 Mapper 비율8개, 잘못된 통계 조건의 폼/결과 계약, 페이지 경계·감소, 충돌의 소유권/초안/최신 모델, 로그인 실패와 가입 redirect 계약.
- 브라우저 시험은 전용 Tomcat localhost:8082와 review_system_test를 사용했다. 각 입력·기대값·실제값은 browser-results.json에 기록했다. 체크 수는 시나리오 수나 사용자 만족도 수가 아니다.
- 기존18개 회귀에서 트랜잭션 롤백·동일 UUID 중복·같은 날 별개 감상·소유권/CSRF/SQL 바인딩·NULL 경계·재감상·대표 평점·공용 작품 참조 보호를 재확인했다.
- 실제 UI에서 삭제 확인 후 **취소**는16건 유지, **실제 삭제**는15건/1페이지로 감소했다. 과거 감상 추가는 현재 시청 중 상태를 유지했다. 최신NULL 이후 이전 유효5.0을 대표로 유지,3.0 수정 후 재계산, 유효 기록 실제 삭제 후0%/대표 없음, 공용 작품과 현재 상태 보존을 확인했다.
- ‘14번째 감상’은 전체 이력의 감상 순번14이다. 첫 감상 이후 재감상 추가는13회이며 ‘14번째 재감상’으로 세지 않는다. 기간 밖 첫 감상과 최신NULL·기간 밖 평점은 기존 SQL과 회귀 시험으로 유지한다.
- 이번 자동화 호출 시간·일반 내비게이션 시간을 PER-001 입력 오류3초 값으로 기록하지 않았다. 기존2026-10-13 측정은 당시 조건의 결과로 유지했다. 조회/통계 목표 최초2초·반복1초는 **팀 확정 전 기준안**이다.

첫 시험 실행에서 새 가입 redirect 시험 데이터의 필수 메일 누락으로1개 실패했다. 합성 시험 입력에 메일을 추가한 뒤 재실행했고 최종23개가 통과했다. 브라우저 도구의 캡처/뷰포트 설정은 활성 탭·재로드로 확인했으며, 치수를 확인한 반응형 검증만 결과로 사용했다. 도구 오류를 앱 결함이나 성능 측정으로 바꾸지 않았다.

## 데이터 보존·정리

앱 review_system의 **회원1·작품4·완료 기록6·현재 상태3·장르8·작품장르5·요청원장0**은 시험 전후 행 내용 SHA256과 건수를 대조하여 동일함을 확인했다. 앱 DB와 시연 데이터를 삭제하거나 초기화하지 않았다.

통합시험은 이름이 review_system_test인지 검사한 뒤 해당 시험 DB의 합성 데이터만 초기화한다. 브라우저 fixture는2회원·10작품·57기록을 생성했다. 생성한 접두어·사용자/작품/기록 ID와 기간별 기대값은 fixture.json에 있다. UI에서 추가한 가입 회원·작품·기록도 같은 접두어/작성자를 사용했다. 종료 시 그 접두어의3회원과 연결한 시험 자료만 정리했고 잔여 fixture 회원0을 확인했다. 임시 회원 비밀번호 파일은 프로젝트 밖에 두고 정리했다.

Git 저장소가 없어 Git diff/commit 대신 소스 백업 ZIP과 파일 해시로 비교했다. 수정 전 소스 백업은 로컬 output/fix-20261014/before-source.zip이다. 기존 분석·증거·DB schema·pom 등58개 역사 파일의 해시가 동일했다. 원본 HWP와 회의록은 변경하지 않았고 새 수정본에 중복 첨부하지 않았다.

## 팀 후속과 미실행

고현진은 #18–24의 기록/상태/통계 계약과 독립 검산, 조우성은 #13·14·17·22의 회원/작품/조회 및 #28 교차 시험, 구서준은 #27/#31의 UI·문서·범위/일정 조정을 이어간다. 대표 담당 요구사항을 구서준으로 일괄 변경하지 않는다. 팀원의 실제 검토일·결과·인수는 각 요구사항에 남긴다.

물리 스마트폰·다른 브라우저·스크린 리더·HTTPS/Secure 쿠키/TLS DB·TMDB/API 이용 조건·게시판/첨부·동시 부하/장시간 안정성·팀원 검토/인수는 미실행이다. 새 PC 전체 재설치도 미실행이다. 조건부3개 적용, 정확한 팀 일정, 성능 허용 기준과 개인정보 보관/삭제·연락 창구·백업 정책은 팀 합의가 필요하다. 구체 기준안과 다음 결정 방법은 team-handover.md에 있으며 확정 정책으로 게시하지 않는다.

레드마인 #12는 수정 전 등록 완료로 유지한다. #32는 코드 수정·명시한 비율/회귀 검증 범위, #33은 F02–F08·추가 보완·문서/자료 등록 범위를 관리한다. 요구사항의 팀 검토·인수는 별도 단계이다. 실제 등록 링크·저장 확인은 레드마인 #33 및 로컬 docs/redmine-followup-20261014.md에 남긴다. Git push·외부 배포·원본 제안서 변경은 수행하지 않았다.
