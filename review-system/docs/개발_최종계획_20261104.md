## 3. 대표 사용 흐름과 화면 변경

대표 흐름: **작품 검색 → 작품 선택 → 기존 내 이력 확인 → 새 감상 저장 → 이전 감상과 비교 → 활동·장르 통계 확인**.

외부 검색과 로컬 검색의 건수·페이지를 합산하지 않는다. 장르별 로컬 필터를 외부 검색에도 적용한 것처럼 표시하지 않는다. 검색 실패 시 기존 검색어를 유지하고 ‘등록된 작품에서 찾기’·‘직접 등록’ 링크를 제공한다.

포스터는 외부 이미지 경로를 사용하고 사용자 업로드는 추가하지 않는다. 누락·이미지 로딩 실패·네트워크 단절 시 대체 표지와 텍스트를 표시한다.

## 4. 재감상 비교의 정확한 의미

### 감상평 비교

- 현재 선택한 기록의 **바로 앞 감상 기록** 1건을 같은 회원·같은 작품의 전체 이력에서 조회한다. 순서는 감상일→생성시각→기록 ID이다.
- 이전 기록의 평점이나 감상평이 비어 있어도 그 기록을 임의로 건너뛰지 않는다. ‘미평점’·‘감상평 없음’으로 표시한다.
- 첫 기록에는 이전 감상이 없다는 안내만 제공한다. 여러 기록 중 임의의 두 건을 고르는 별도 비교 도구는 이번에 만들지 않는다.
- 두 원문을 읽으며 사용자가 생각 변화를 판단한다. 시스템이 감정·취향 변화의 원인이나 방향을 자동 판정하지 않는다.

### 평점 변화

- 기존 계약대로 **현재보다 앞선 최신 유효 평점**을 비교한다. 미평점은 건너뛴다.
- 바로 앞 기록과 유효 평점 기준 기록이 다를 수 있으므로, 평점 변화에 비교 기준 날짜·원본 기록 링크를 함께 표시한다. ‘이전 감상평’과 같은 기록이라고 오인하게 만들지 않는다.
- 현재가 미평점이면 수치 변화는 표시하지 않는다. 0점으로 치환하지 않는다. 같은 평점은 ‘변화 없음’이다.
- 예: 9/1 3.0점/감상평A → 10/1 미평점/감상평B → 11/1 4.5점/감상평C. 감상평 비교는 B↔C, 수치 비교는 9/1 대비 +1.5점이다.
- 과거 기록 추가·날짜 변경·삭제 후 이전 기록과 평점 기준을 다시 계산한다. 필터·페이지 밖 기록도 비교 기준에 포함한다.
- ‘과거의 생각 보존’은 재감상을 새 행으로 저장한다는 뜻이다. 기존 기록 수정의 모든 버전을 영구 보존하는 변경 이력 기능을 추가한다는 뜻은 아니다.

## 5. TMDB 연동 계약

### 검색·저장

- 영화 `/search/movie`, 드라마 `/search/tv`, 상세 `/movie/{id}`·`/tv/{id}`를 서버에서 HTTPS로 호출한다. 한국어 `ko-KR`, 성인 결과 제외, TMDB 원본 페이지 순서를 사용한다. 배우·인물·회차 검색은 없다.
- TMDB는 검색과 작품 정보 공급원이다. 자체 DB는 선택한 공용 작품, 회원별 감상·상태와 통계 원본을 보관한다. 전체 카탈로그 일괄 수집은 하지 않는다.
- 새 작품 가져오기는 로그인 회원에게 허용한다. 서버가 검증한 외부 ID로 상세를 재조회하여 새 공용 작품을 만들거나 동일 작품을 재사용한다. 클라이언트가 보낸 제목·장르·소개를 신뢰해 저장하지 않는다.
- 기존 공용 작품의 수정·삭제·수동 작품과 외부 작품의 연결은 관리자 권한을 유지한다. 신규 외부 작품 가져오기와 기존 작품 재연결을 UC #187·권한표에서 구분한다.
- 제안서 SFR-005의 ‘외부 연결은 관리자’ 문구에 비해 회원의 신규 가져오기를 명시적으로 허용하는 권한 명세 개정이다. 이를 기존 규칙과 동일하다고 표현하지 않고 #17/#25/#31에 사유·영향을 기록한다. 관리자가 지정한 외부 ID로 기존 작품을 바꾸는 권한은 회원에게 열지 않는다.
- `source+media_type+external_id` 유일 키를 사용한다. 영화 ID와 TV ID의 숫자가 같아도 별개 작품이다. 중복 클릭·다른 회원 동시 선택도 한 작품을 재사용하도록 처리한다.
- TMDB 네트워크 호출은 DB 쓰기 트랜잭션 밖에서 끝낸다. 작품+장르 저장은 한 트랜잭션으로 처리하며 유일 키 충돌은 기존 작품 재조회로 복구한다. 롤백된 트랜잭션을 계속 사용하지 않는다.
- 작품 가져오기와 감상 저장은 별개 명령이다. 가져오기 성공 후 감상 작성을 취소하면 공용 작품만 남을 수 있으며 감상 건수는 늘지 않는다.

### 저장 데이터·마이그레이션

- 기존 `work.id`와 모든 개인 기록 FK를 유지한다. 개발용 기본 작품은 10개 안팎, 회원·이력은 합성 데이터로 준비한다. 성능용 1,000작품/10,000기록 DB는 별도이다.
- `work`의 기존 source·media_type·external_id·title·release_year·synopsis를 재사용하고, nullable `poster_path`, `external_fetched_at`를 추가하는 명시적 마이그레이션을 작성한다.
- 장르 매핑은 `external_genre_map(source, media_type, external_genre_id, genre_id)`로 분리한다. 기존 `genre`/`work_genre`와 통계의 고유 작품 집계는 유지한다.
- 외부 장르 목록과 팀의 기존 장르표를 대조한 명시적 매핑 초기 데이터를 작성한다. 영화·TV 장르 ID를 유형별로 구분하고 외부 ID를 로컬 PK로 사용하지 않는다. 복합 장르의 임의 분해·유사 이름 자동 병합은 하지 않는다.
- 미매핑 장르는 명시적 ‘미분류’로 처리하고 관리자 매핑 후 영향을 받는 작품 장르만 갱신한다. 일반 회원에게 공용 장르 생성·수정 권한을 부여하지 않는다. 갱신 시 통계 변화 원인을 기록한다.
- 제목은 한국어 값 우선·없으면 원제, 영화는 개봉일·TV는 첫 방영일의 연도를 사용한다. 식별 제목이 없거나 기존 200자 한도를 넘으면 가져오기를 거부하고 원본 링크·직접 등록을 안내한다. 소개는 선택이며 1,000자까지 안전한 유니코드 경계로 발췌하고 외부 소개 발췌임을 표시한다. 전체 정보는 TMDB 상세 원본 링크로 확인한다. 연도 없음은 NULL, 포스터 없음은 대체 표지이다. 외부 입력 정규화 정책을 DTO에 고정한다.
- 제목이 같은 수동 작품은 자동 병합하지 않는다. 개발용 연결은 기존 작품이 없는 경우에 초기 연동을 하거나, 관리자가 신원을 확인해 기존 `work.id`에 외부 식별자를 부여한다. 이미 같은 외부 작품이 다른 로컬 ID에 있으면 자동 이동하지 않고 충돌 안내를 한다. 전체 데이터 병합 도구는 이번 범위에 없다.
- 스키마 변경 전 개발 DB를 백업하고 시험 DB에서 기존 기록·상태·FK 개수를 대조한다. 앱 시작 때 스키마를 초기화하지 않는다.

### 장애·보호·이용 조건

- 서버 외부 설정에 `TMDB_READ_ACCESS_TOKEN`을 두고 클라이언트·URL·저장소·로그에 노출하지 않는다. `tmdb.enabled=false` 또는 키 없음은 외부 검색만 비활성화하며 앱 전체 시작을 막지 않는다.
- 서버가 호출하는 호스트를 TMDB 공식 API로 고정한다. 사용자 입력 URL을 받아 대리 호출하지 않는다. 개인 기록·감상평·회원 식별자는 외부 요청에 포함하지 않는다.
- 연결 2초·읽기 3초·사용자 작업 전체 약 6초의 상한을 초기 구현값으로 두고 실제 환경에서 측정한다. 무한 재시도·자동 반복 호출은 하지 않는다. 입력 오류3초 기준과 별도이다.
- 인증 실패, 429, 5xx, 연결/읽기 시간 초과, JSON 오류, 0건을 구분한다. 429는 요청을 중단하고 재시도 안내를 제공하며 로컬 대안을 유지한다.
- 외부 JSON의 크기·필드·길이를 제한하고 안전하게 출력한다. 검색어 입력 오류는 외부 호출 전에 검사한다.
- 포스터 표시는 CSP `img-src`에 `https://image.tmdb.org`만 추가한다. 기존 `default-src`·script·frame 정책을 완화하지 않는다.
- 출처 영역에 승인 로고와 공식 고지문을 둔다. FAQ와 현재 이용약관의 문구 차이는 개발 시 현재 약관을 우선 확인하고, 원문을 임의 번역해 공식 고지문을 대신하지 않는다.
- 11/04 공식 API 이용약관 화면에서 6개월 초과 캐시 제한과 종료 시 콘텐츠 삭제 조항을 확인했다. ‘DB에 영구 복사’ 정책을 사용하지 않는다. 외부 취득시각을 저장하고 180일을 내부 만료 기준으로 관리한다. 사용 시 재조회·갱신하고, 만료 콘텐츠는 갱신 실패 시 숨기며 정리 절차에서 제거한다. 백업도 정리 대상에 포함한다.
- 정리 도구는 외부에서 가져온 작품 메타데이터·포스터 경로·외부 장르 연결만 처리한다. 개인 감상 기록·평점·감상평·현재 상태·안정적인 로컬 작품 ID는 삭제하지 않는다. 이용 종료/정리 시 가져온 제목·소개 등을 남겨두지 않고 대체 표시와 직접 입력 복구 경로를 제공한다. 외부 식별자까지 삭제해야 하는 종료 절차를 별도로 명시한다.
- 180일은 이번 계획의 보수적인 관리값이며, 이것만으로 약관 전체 준수를 인증하지 않는다. 저장·갱신·삭제·취득 정보의 구분과 정리 명령을 #25/#70의 초기 검토 기록에 남긴다. 과제 이후 계속 운영하려면 이 절차를 이어서 수행한다.

공식 확인 자료: [검색 흐름](https://developer.themoviedb.org/docs/search-and-query-for-details), [영화 검색](https://developer.themoviedb.org/reference/search-movie), [TV 검색](https://developer.themoviedb.org/reference/search-tv), [이미지](https://developer.themoviedb.org/docs/image-basics), [429](https://developer.themoviedb.org/docs/rate-limiting), [FAQ/출처](https://developer.themoviedb.org/docs/faq), [API 이용약관](https://www.themoviedb.org/api-terms-of-use). 공식 문서 확인은 API 실제 호출 성공의 증거가 아니다.

## 10. 시험 계획과 완료 기준

독립 시험은 TMDB 5개(T02-05~09)를 포함한 **총 38개 예정·미실행**이다. #90은 #89의 증거 검산이며 독립 실행 사례 수에 더하지 않는다. 기존10/16 자동시험 건수도38에 합산하지 않는다.

| --- | --- | --- |

429·장애는 통제된 합성 응답으로 재현한다. 실제 서비스를 과도하게 호출하거나 의도적으로 장애를 유발하지 않는다. 모의 응답 통과와 T02-09 실제 호출 근거를 구분한다.

기존 T09-05에 ‘이전 감상은 미평점/감상평B, 이전 유효 평점은 더 오래된 A’ 사례와 두 원문의 안전 출력·기준 날짜를 추가한다. T03-04는 과거 삽입·날짜 수정·삭제 뒤 이전 감상 재선택까지 확인한다. UI T05는 PC/390px에서 비교·포스터 실패·긴 감상평·키보드 동작을 확인한다.

최종 인수에는 다음이 필요하다.

1. 적용17개 요구의 설계·코드·시험·실제 증거가 연결되고 주요 결함이 수정·재시험됨.
2. 영화·TV 실제 TMDB 검색과 중복 없는 작품 저장이 확인됨.
3. 같은 작품3회 감상의 원문·평점·기준 날짜를 비교할 수 있고 수정/삭제 후 재계산됨.
4. 다른 회원·관리자도 타인의 기록을 읽거나 수정할 수 없음.
5. API 장애에도 기존 기록·현재 상태·로컬 조회·통계가 동작함.
6. 기존 COMPLETE/PAST/상태만완료·NULL·기간 대표 평점·중복 제출·충돌·롤백 계약을 통과함.
7. 실제 실행 환경·마이그레이션·키 설정·보관/정리 절차·미실행 항목·다른 팀원의 독립 검토가 기록됨.

## 11. 대표 발표·시연

‘같은 작품이 달라진 것이 아니라, 기록을 통해 달라진 나의 감상을 돌아본다’는 사용 목적을 먼저 보여 준다.

1. TMDB에서 작품을 찾아 선택한다. 제목·유형·연도로 식별하고 자체 DB의 작품에 연결한다.
2. 첫 감상3.0점과 감상평을 저장하고, 과거 감상 추가로 두 번째 미평점·감상평, 세 번째4.5점·새 감상평을 남긴다.
3. 세 번째 기록에서 바로 앞 감상평과 비교하고, 평점은 첫 기록 대비+1.5점임을 날짜와 함께 설명한다.
4. 기간 통계에서 기록 수·작품 수·재감상 추가 횟수·장르 대표 평점과 원본을 검산한다.
5. 외부 연결 실패 상황에서도 저장된 이력·비교·통계를 계속 확인한다.

이 시연의 시스템 근거는 회원별 권한, 공용 작품/개인 기록 분리, 외부 삼중 키, 새 INSERT 재감상, 저장 트랜잭션, 전체 이력 순서와 기간 집계이다.
